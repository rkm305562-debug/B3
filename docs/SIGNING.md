# توقيع التطبيق للنشر على Google Play

تم إنشاء مفتاح توقيع حقيقي (Upload Key) خاص بك، منفصل تمامًا عن مفتاح debug.
هذا الملف يشرح كيف تُفعّله في GitHub Actions ليُستخدم تلقائيًا عند بناء نسخة الإصدار (Release).

## ⚠️ تحذير أمني مهم جدًا
- ملف `my-upload-key.jks` وكلمتا المرور **لا يُرفعان إلى GitHub أبدًا** (تم استثناؤهما في `.gitignore`).
- إن فقدت هذا الملف أو كلمتَي المرور، **لن تستطيع نشر أي تحديث مستقبلي لنفس التطبيق على Google Play** تحت نفس بصمة التوقيع (ما لم تكن مسجَّلاً في خدمة Google Play App Signing، راجع الملاحظة أسفل الصفحة).
- احتفظ بنسخة احتياطية من الملف وكلمتَي المرور في مكان آمن (مدير كلمات مرور، تخزين سحابي مشفّر خاص، إلخ) — ليس في أي مستودع Git عام أو خاص.
- لا تشارك هذا الملف أو كلمتَي المرور مع أي شخص لا تثق به تمامًا.

## خطوات التفعيل في GitHub

1. اذهب إلى مستودعك على GitHub → **Settings** → **Secrets and variables** → **Actions**.
2. أضف 3 أسرار جديدة (New repository secret) بالضبط بهذه الأسماء:

   | الاسم (Name) | القيمة (Value) |
   |---|---|
   | `RELEASE_KEYSTORE_BASE64` | محتوى ملف `my-upload-key.jks` بصيغة Base64 (الملف المرفق `keystore_base64.txt`) |
   | `RELEASE_STORE_PASSWORD` | كلمة مرور المخزن (من الملف المرفق `signing-credentials.txt`) |
   | `RELEASE_KEY_PASSWORD` | نفس كلمة المرور أعلاه (صيغة PKCS12 تفرض تطابق الكلمتين) |

3. بعد إضافة الأسرار الثلاثة، أي عملية بناء جديدة عبر GitHub Actions ستُوقّع نسخة الإصدار (Release) بمفتاحك الحقيقي تلقائيًا، وستجد أيضًا:
   - `ZainQH-Chat-Release-APK` — ملف APK موقَّع، صالح للتجربة المباشرة على جهاز.
   - `ZainQH-Chat-Release-AAB` — ملف Android App Bundle، **هذا هو الملف الذي يجب رفعه فعليًا إلى Google Play Console** (Google تطلب AAB وليس APK للتطبيقات الجديدة).

4. إن لم تُضِف الأسرار، سيستمر البناء بالعمل للاختبار فقط، لكنه سيُوقّع النسخة "الإصدار" بشهادة debug مؤقتة **مع تحذير واضح في سجل GitHub Actions** — لا ترفع تلك النسخة أبدًا لمتجر Google Play.

## معلومات الشهادة (لأي API يطلب بصمة التوقيع، مثل Google Sign-In أو خرائط Google)
راجع ملف `signing-credentials.txt` المرفق — يحتوي بصمتي SHA1 وSHA256 الكاملتين.

## ملاحظة عن Google Play App Signing
عند إنشاء أول إصدار على Google Play Console، تُقدَّم لك خدمة **Play App Signing** (تُفعَّل تلقائيًا لأي تطبيق جديد تقريبًا). في هذه الحالة:
- مفتاحك (`my-upload-key.jks`) يُستخدم فقط "لرفع" (Upload) الإصدارات إلى Google — يُسمّى "Upload Key".
- Google تحتفظ بمفتاح التوقيع الفعلي النهائي للمستخدمين بشكل منفصل وآمن لديها.
- هذا يعني أنه حتى لو فقدت مفتاح الرفع لاحقًا، يمكنك طلب إعادة تعيينه (Upload Key Reset) من Google Play Console دون فقدان القدرة على تحديث التطبيق — لكن هذا إجراء يستغرق وقتًا ويتطلب تحققًا، فالأفضل دائمًا حفظ المفتاح جيدًا من البداية.
